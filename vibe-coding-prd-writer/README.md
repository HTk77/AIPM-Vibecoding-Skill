# vibe-coding-prd-writer

> 撰写 Vibe Coding PRD —— 写给 AI 编程工具直接消费、能照着干活的产品需求文档。

**版本:** v0.2.0 | **作者:** 赫庭 | **状态:** 个人自用,持续迭代

---

## 这个 skill 是什么

一个帮助产品经理(尤其不会写代码的 PM)在 vibe coding 场景下产出**结构化、模块化、AI 能直接执行**的 PRD 的工作流 skill。

**与传统 PRD 最大区别:** 这份 PRD 的读者是 AI 编程工具(Claude Code / Cursor / Lovable / Bolt / Windsurf 等),不是开发团队。因此模糊度必须更低、验收必须可观测、边界必须显式。

---

## 解决什么问题

| 痛点 | 本 skill 怎么解 |
|------|---------------|
| 拿到模糊想法就开写,改 4 次 PRD | **强制 4 阶段流程 + 3 次用户确认点** |
| AI 写代码总加自己的戏 | **强制"边界声明"模块,显式列不做的事** |
| AI 写完说"做完了",其实没做对 | **每个功能必含可勾选验收标准** |
| AI 项目和功能产品混着写 | **§1 显式判断 + AI 项目 5 项额外内容** |
| Prompt 凭印象写,跑下一个项目时 SKILL 就漂了 | **示例改为模板 + 6 行业微示例** |
| 触发词太宽,污染日常 PRD 工作流 | **明确 / 模糊 / 严禁三档触发,模糊场景先反问** |

## 怎么触发

### ✅ 明确触发(skill 立即执行)

- "写 vibe coding PRD"
- "写 vibe PRD"
- "AI 能直接读的需求文档"
- "AI 能执行的需求文档"
- "给 AI 看的 PRD"
- "Claude Code 的 PRD" / "Cursor 的 PRD"
- "我要用 AI 写代码,先做 PRD"

### 🟡 模糊触发(先反问场景再决定)

当你只说 "写 PRD" / "撰写需求文档" / "做产品规格" 时,skill 会先问:

> "这份 PRD 是给开发团队看,还是给 AI 编程工具直接执行?"

只有后者才走 vibe coding 流程。

### ❌ 严禁触发(自动跳过,不污染传统工作流)

- 给开发团队评审的传统 PRD
- 已有敏捷开发流程的团队
- 单纯的需求收集 / 用户访谈 / 竞品分析
- 撰写 BRD / MRD / TRD

## 输出长什么样

skill 触发后,会按 **4 阶段流程 + 3 个用户确认点** 协作:

```
阶段 1: 输入对齐 ──→ ✋ 确认 #1: "信息齐了吗?"
阶段 2: 产品架构设计 ──→ ✋ 确认 #2: "架构对吗?"
阶段 3: PRD 撰写(5 必写模块)
阶段 4: 二次确认 Walkthrough ──→ ✋ 确认 #3: "PRD 没歧义?"
```

**5 必写模块:**
1. 项目身份卡(AI 项目额外含三要素自检)
2. 功能契约(每条 = 用户故事 + 触发 + 输入输出 + 验收 + 优先级)
3. 边界声明(不做的事 + 取舍 + 兜底 + AI 项目合规风险)
4. 设计与技术契约(技术栈 + 设计 token + 数据 schema + AI 项目模型选型 + 评测体系)
5. 验收清单(端到端测试场景 + AI 项目数据采集三渠道)

## 快速开始

### 第一次使用

1. 在 Claude Code 中说一句明确触发词(如 "我要写 vibe coding PRD")
2. skill 会先问你 "上一步资料齐了吗",列出必填项让你确认
3. 进入架构设计阶段,产出 3+1 项让你 review
4. 按 5 模块顺序写完 PRD
5. Walkthrough 二次确认,锁定 v1.0

### 验证 skill 是否正常

打开新对话试这两句话,验证触发逻辑:

| 测试 | 期望反应 |
|------|---------|
| "帮我写一个用户管理系统的 PRD" | 应反问"给开发团队还是 AI 编程工具" |
| "我想用 Claude Code 做一个小工具,先写个 vibe coding PRD" | 应直接走 4 阶段流程 |

## 常见问题

### Q1:可以不走 4 阶段流程,直接让 skill 写 PRD 吗?
不可以。流程是 skill 的核心价值。跳过流程 = AI 自说自话,不是和你对齐过的产物。

### Q2:每次都要确认 3 次,会不会太烦?
不会。3 次确认平均消耗 5 分钟,换来的是不用改 4 次 PRD 的成本。性价比极高。

### Q3:AI 项目和功能产品的判断标准?
看 SKILL.md §1.1。简单说,只要底层调用 LLM / 涉及生成式 / RAG / Agent / 多模态,就是 AI 项目。

### Q4:示例为什么不再有完整 PRD?
v0.1.0 的完整示例(基于赫庭 AI 圆桌会议)迁移性差,导致下次做不同主题项目时 AI 仍然写得"像赫庭项目"。v0.2.0 改为**模板 + 6 行业微示例**,迁移性更强。

### Q5:可以把这个 skill 分享给其他 PM 同事吗?
可以,但建议先你自己跑 3-5 个真实项目验证后再分享。skill 描述里有"严禁触发"清单防止污染同事日常工作流。
