# Vibe PRD 跨行业微示例

> 不是完整 PRD,只是"某个模块在某种产品下长什么样"的片段。
> 为了避免 SKILL 输出"看着像赫庭项目"的问题,本文档故意覆盖 6 个不同行业。
> AI 写 PRD 时,**找最接近你的项目类型,看那一段示例的结构**(而非内容)。

---

## 示例 A:C 端工具 — 每日情绪记录小程序

### 模块 2 功能契约片段(F1 单条示范)

```markdown
### 2.1 F1:每日情绪打卡

**用户故事:** 作为一个想觉察自己情绪的成年人,我想要在 30 秒内记录今天的情绪状态,以便周末回顾时看到自己一周的情绪曲线。

**描述:** 用户进入首页,点击"今日打卡",从 5 个表情选项中选 1 个,可选填一句话备注,确认后保存到本地。

**触发条件:** 用户在首页点击"今日打卡"按钮,或每日 21:00 推送提醒后点击进入。

**输入:**
- 必填:5 选 1 表情(😊😐😔😡😴)
- 选填:1 句话备注(≤ 50 字)

**输出:**
- 写入本地存储 + 当日打卡卡片高亮 + 周历视图新增今日色块
- 7 日内已打卡 → 显示连续打卡天数

**边界情况:**
- 同日多次打卡 → 弹窗"今天已打卡,要覆盖吗?"
- 备注超 50 字 → 输入框红色边框 + 字数提示
- 离线状态 → 仍可打卡(本地存储),恢复后不需同步

**验收标准:**
- [ ] 30 秒内能完成"打开 → 选表情 → 保存"流程
- [ ] 打卡后立即在周历可见对应色块
- [ ] 飞行模式下仍能打卡且数据不丢
- [ ] 同日重复打卡有覆盖提示

**优先级:** P0
```

## 示例 B:B 端工具 — 客户反馈管理后台

### 模块 3 边界声明片段

```markdown
## 3. 边界声明

### 3.1 不做的事

| 不做 | 原因 |
|------|------|
| 客户主动给我们发消息(双向 IM) | 这是客服系统,不是反馈管理。本系统只读用户已留下的反馈 |
| 自动给客户回复 | 涉及业务话术敏感,人工兜底 |
| 反馈分类的机器学习自动打标 | P1 才考虑,现阶段人工打标够用 |
| 多租户(多家公司用) | 本系统是公司内部用,无需 SaaS 化 |

### 3.2 取舍说明

- **选 飞书多维表格集成 而非 自建表单系统:** 全公司已用飞书,降低学习成本
- **选 邮件通知 而非 短信:** 内部用,邮件够用,短信成本高

### 3.3 兜底策略

| 异常 | 用户看到什么 | 系统做什么 |
|------|------------|-----------|
| 飞书 API 失效 | 顶部黄条 banner "数据同步暂停" | 本地缓存 + 30s 重试 + 失败超 3 次邮件告警 |
| 反馈量暴增(每天 > 1000 条) | 提示 "今日反馈 X 条" | 自动分页 + 后台异步处理 |
```

## 示例 C:AI 产品 — 智能客服(含 AI 三要素)

### 模块 1 项目身份卡 + AI 三要素自检片段

```markdown
## 1. 项目身份卡

| 字段 | 内容 |
|------|------|
| 产品名 | 智能客服小客 / Xiao Ke AI Support |
| 一句话定位 | 给中小电商商家的 7×24 小时 AI 客服,直接接入淘宝 / 拼多多旺旺 |
| 目标平台 | Web 后台 + 旺旺接入,商家电脑端使用 |
| 目标用户 | 中小电商店主,日订单 50-500 单,养不起夜班客服,平均 35 岁不懂技术 |
| 核心价值主张 | 1) 5 分钟接入,无需技术;2) 可定制自家产品话术;3) 月度 ¥99 比夜班客服便宜 90% |
| 项目类型 | AI 产品(LLM + RAG) |
| 项目规模 | 小团队 SaaS,目标半年 1000 商家 |

### 1.1 AI 三要素自检(项目级)

| 维度 | 自答 | 评分 |
|------|------|------|
| 用户痛点强度 | 中小商家 23:00-08:00 无人接单 → 流失订单 / 差评。每流失 1 单 ¥80,月均损失 ¥1500-3000。痛点真实强烈。 | **9 分** |
| 数据可获得性 | 商家自己提供 FAQ + 历史订单 + 商品信息(独家)。LLM 兜底通用话术。数据冷启动有压力但可获得。 | **6 分** |
| 算法可实现性 | RAG + GPT-4o-mini / Qwen 即可,客服话术非高难度任务,行业已有 OK 实现。 | **8 分** |

> 三项均 ≥ 3,直接进入 PRD 撰写。**最弱项是数据冷启动**,在 §3 边界声明里需有"前 3 个月需商家配合补 FAQ"的说明。
```

## 示例 D:多 Agent / LLM 角色产品 — 设计与技术契约片段

### 模块 4 节选 + 评测体系

```markdown
### 4.6 模型选型(AI 项目)

| Agent | 模型 ID | 温度 | max_tokens | 理由 |
|-------|--------|------|-----------|------|
| 角色 A(批判型) | DeepSeek-R1 | 0.7 | 1500 | 推理强 + 高 temp 增加发散性 |
| 角色 B(引导型) | Qwen2.5-72B-Instruct | 0.5 | 1500 | 中等 temp 偏稳重,适合温和提问 |
| 角色 C(技术型) | DeepSeek-V3 | 0.5 | 1500 | 第一性原理推理 + 价格低 |

### 4.7 数据质量与算力评估

| 维度 | 评估 |
|------|------|
| 数据质量 | 角色 prompt 基于公开互联网资料(verbatim 引用 + 出处),无脏数据 |
| 部署 | 全云端,通过 AIHubMix 一站调度 |
| 单次请求延迟 | 首字节 < 5s(模型正常时) |
| 并发能力 | 单用户 3 个并行模型调用,不构成并发挑战 |

### 4.8 评测体系

| 评测维度 | metric | 评测集来源 | 通过门槛 | 频率 |
|---------|-------|----------|---------|------|
| 角色一致性 | "看起来像本人"打分 | 5 题人工标准答案 | ≥ 4/5 | 每次改 prompt |
| 反驳能力 | 是否引用其他角色发言 | 10 个多角色场景 | ≥ 80% 引用 | 每周 |
| 输出质量 | 信息密度 + 段落感 | 用户主观打分 | ≥ 4/5 | 滚动收集 |
```

## 示例 E:内容产品 / UGC 平台 — 验收清单片段

### 模块 5 验收清单

```markdown
## 5. 验收清单

### 5.1 正常路径

- [ ] **新用户首发帖:** 注册 → 进首页 → 点"+发布" → 输入文字 + 上传 1 张图 → 点击发布 → 帖子出现在首页且 60 秒内被推送给 ≥ 10 个匹配用户
- [ ] **互动:** 看到他人帖子 → 点赞 → 计数 +1 且头像出现在点赞列表
- [ ] **评论:** 点评论 → 输入 → 提交 → 评论出现在帖子下,作者收到通知
- [ ] **个人主页:** 点头像 → 看到自己所有帖子 + 关注 / 粉丝数

### 5.2 异常路径

- [ ] **图片超 10MB:** 提示"图片过大,自动压缩中" + 30 秒内压缩并继续发布
- [ ] **断网时发布:** 提示"网络异常,已保存草稿" + 恢复后弹"是否发布草稿"
- [ ] **敏感词内容:** 提示"内容含违规词,请修改" + 高亮敏感词位置(不直接禁发,允许编辑)

### 5.3 数据采集三渠道(UGC 平台核心)

| 渠道 | 落地 |
|------|------|
| 用户原声 | 首页底部"反馈"入口 + 内容举报功能 |
| 数据埋点 | 发帖率 / 互动率 / 留存(D1/D7/D30) / 单次会话时长 |
| 效果评测 | 推荐准确率(用户停留 ≥ 5s 占比)+ 内容审核准确率(漏审 / 误审) |
```

## 示例 F:工具流 / 自动化产品 — 模块拆分片段

### 阶段 2 架构设计片段(自动化营销工具)

```markdown
## ① 产品形态
工具流型 SaaS,可视化拖拽节点配置营销自动化(类似 Zapier 但聚焦电商场景)

## ② 核心用户流
登录 → 选模板 / 新建空白工作流 → 拖拽节点(触发 / 条件 / 动作) → 配置每个节点 → 测试运行 → 启用 → 监控

## ③ 模块拆分

| 模块 ID | 模块名 | 职责 | 与其他模块关系 |
|---------|-------|------|--------------|
| M1 | 工作流编辑器 | 可视化拖拽 + 节点配置 + 校验 | 输出工作流 JSON 给 M3 |
| M2 | 节点库 | 30+ 预制节点(触发器 / 条件 / 动作) | 被 M1 引用 |
| M3 | 工作流运行时 | 接收 JSON 实际执行 | 调用 M4 第三方,写日志到 M5 |
| M4 | 第三方集成 | 微信 / 支付宝 / 抖店 / 淘宝 API | 被 M3 调用 |
| M5 | 监控与日志 | 运行历史 / 错误告警 | 给 M1 显示节点错误状态 |

## ④ AI 介入点(仅 AI 项目)

| 介入点 | 模块 | LLM 任务 | 输入 | 输出 |
|--------|------|---------|------|------|
| AI-1 | M1 | 自然语言转工作流(如"每周一给老客户推优惠"→拼好节点) | 用户自然语言描述 | 工作流 JSON 草稿 |
| AI-2 | M2 | 节点配置助手(用户改节点参数时给建议) | 当前节点 + 上下文 | 字段填充建议 |
```

## 怎么用这些示例

1. **找最像你项目类型的那个**(C 端工具 / B 端 / AI 产品 / 多 Agent / 内容 / 工具流)
2. **看示例的"结构"而不是"内容"** —— 字段顺序、详细度、用词风格
3. **替换具体内容**为你的项目
4. **不要复制粘贴文字** —— 内容必须基于你项目的真实情况

> 没有覆盖你的行业?用最相似的一个 + 你自己的判断。
> 写完后用 [`checklist.md`](./checklist.md) 自查。
