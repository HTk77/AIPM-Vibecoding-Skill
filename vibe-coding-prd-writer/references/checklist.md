## ★ 流程合规(最高优先级,8 条)

- [ ] **F1** 阶段 1 输入对齐做了?(列了输入资料清单 + 检查齐全)

## 总分判定

**必通过项(阻断性):**
- ★ 流程合规(F1-F8) — 任一不过 = 重新走流程
- A 模块完整性 — 缺模块 = 不合格
- AI 项目的 B-AI / C-AI / D-AI / E-AI / VC-AI

**严重不足:**
- B/C/D/E/F 失分超过 30% = 该章重写

**可优化:**
- G/H/I/J 失分 = 不阻塞执行,但建议补

## 反向检查:5 个让 PRD 烂掉的关键症状

如果你的 PRD 有以下症状,**立即推翻重写**,逐条修补救不了:

1. **写完了但你自己说不清"AI 怎么 1:1 实现"** → 太模糊
2. **跑给同事看,需要 5 分钟以上才能讲清楚** → 太复杂或没浓缩
3. **每个功能验收都写"测试通过"** → 没真验收
4. **没有"不做什么"章节** → 必然 scope creep
5. **设计/技术写"开发评估后决定"** → 缺锁定,后续返工保证

### AI 项目额外 3 个症状

6. **没做 AI 三要素自检就直接写 PRD** → 立项就埋雷
7. **没写评测指标** → 没法判断 AI 是否做对了
8. **没合规风险评估** → 上线前法务踢出局

## 自查 SOP(执行流程)

```
Step 1: 流程合规检查(★F1-F8)
        失分 → 立即回到撰写流程对应阶段补
        全过 → Step 2

Step 2: 模块完整性 + AI 项目额外项(A/B/C/D/E/F + AI 子项)
        失分超 20% → 该模块重写
        失分 < 20% → 逐条修

Step 3: 同事 / 不熟悉 AI 测试
        让一个不知道项目的 AI 窗口读 PRD,然后问:"列出你能直接执行的 5 个 P0 功能 + 3 个不做的事"
        AI 答不全 → 你的 PRD 不够"AI 友好",回去改

Step 4: G/H/I/J 类一次梳理(解耦 / 友好 / 可视化 / 元数据)
```

## 一句话总结

> **"AI 读完你的 PRD,如果还要问'然后呢'、'用什么'、'怎么算做完',就不合格。"**
